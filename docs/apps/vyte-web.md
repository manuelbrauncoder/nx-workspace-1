# vyte-web

The web app of vyte: a host plans an event, keeps its guest list and shares a personal link with every guest. So far it is the frame: app shell, sign-in, the legal pages (text from the API, edited by admins), a placeholder start page and the complete API layer for `vyte-api`. The pages of the [specification](../vyte/spec.md#7-web-draft) follow. Built like `angular-base` on the same libs, so this page only covers what differs.

| Item    | Value                                                                                     |
| ------- | ----------------------------------------------------------------------------------------- |
| Folder  | [apps/vyte-web](../../apps/vyte-web)                                                      |
| Tags    | `type:app`, `scope:vyte`                                                                  |
| Locally | <http://localhost:4300>, talks to `vyte-api` on <http://localhost:3300/api/v1>            |
| Libs    | `core`, `ui`, `styles`, `contracts`, `vyte-contracts`                                     |
| Image   | `ghcr.io/<owner>/nx1-vyte-web`, tag `nx1-vyte-web-v*`, see [Deployment](../deployment.md) |

## Running it

The sign-in needs the API, see [vyte-api](vyte-api.md). Both together:

```bash
pnpm nx run-many -t serve -p vyte-api vyte-web
```

The ports differ from the other products, so all of them run side by side. `build -c watch` and `server` work as for [angular-base](angular-base.md#running-it).

## API layer

`src/api` covers every endpoint of `vyte-api`, each folder with DTO re-export, model, mapper, repository and specs as described in [API and config](../frontend/api-and-config.md). The features use it through their use case; `guests` combines `guests/` with `events/` for the title and state of the event.

| Folder             | Contract                     | What it talks to                                                                     |
| ------------------ | ---------------------------- | ------------------------------------------------------------------------------------ |
| `auth/`            | `@contracts/auth`            | Sign-in, sign-out, `/auth/me`                                                        |
| `account-invites/` | `@contracts/account-invites` | Account links: the admin's list, and creating the account behind `/welcome/:token`   |
| `users/`           | `@contracts/auth`            | Accounts of the admin area                                                           |
| `events/`          | `@vyte/contracts/events`     | Events, their images, the save-the-date and photo-stand settings                     |
| `guests/`          | `@vyte/contracts/guests`     | Guest list, answers a host records, renewing links, address of the CSV export        |
| `team/`            | `@vyte/contracts/team`       | Members, handover, editor invites of the owner                                       |
| `invites/`         | `@vyte/contracts/team`       | An editor invite as the invited person sees it: preview, accept, sign up             |
| `rsvp/`            | `@vyte/contracts/guests`     | The personal page of a guest: invitation, answer                                     |
| `save-the-date/`   | `@vyte/contracts/events`     | The public save-the-date page                                                        |
| `photos/`          | `@vyte/contracts/photos`     | The gallery of the hosts: hide, delete, address of the ZIP download                  |
| `legal/`           | `@vyte/contracts/legal`      | The legal pages: the public text per language, and the admin's list and save of them |

- **`VyteEvent`**: the model of an event is not called `Event`, that name is the DOM event in every file that does not import it
- **Dates** are `Date` in the models. What an event or a guest does not have stays `null`, as on the wire
- **Addresses of files**: `EventImage.url` is part of the model, as with the notes of the base. Where a DTO does not say whose file it is (photos, images behind a token), the repository builds the address: `imageUrl()`, `photoUrl()`, `coverUrl()`. The same goes for downloads the browser fetches itself: `exportUrl()` (CSV), `archiveUrl()` (ZIP), `calendarUrl()` (ICS)
- **Results with two shapes**: `Invitation` and `SaveTheDate` are unions on `past`. After the event they hold the title only
- **Uploads of guests** go one file per request (`UploadsRepository.upload()`). The limit and what is left come with every answer (`Upload.limit`, `Upload.left`), nothing is counted in the app

## Differences to angular-base

- **Look**: the design "Konfetti" in light only, fonts Unbounded (headings) and DM Sans. `FORCED_THEME_MODE` is `'light'`, there is no theme toggle and no `_dark.scss`. `--brand` is the yellow with ink on it, `--primary` the blue; `--decor` and `--soft` are extra tokens. The Konfetti shapes are tokens as well: `--card-border`, `--card-radius` and `--card-shadow` (3px ink border, 28px radius, offset shadow without blur) for cards such as the event cards and the counts, `--chip-border` for pills such as "Vorbei". Text sizes come from `appUiText`, not from the SCSS of a page. `--ring` is the ink, not the blue: the helm controls draw their focus ring at 50%, which keeps the ink at about 3.3:1 on white, the blue would fall to 2.6:1. The values come from the [design](../vyte/design/README.md)
- **No sign-up**: no page, no route, no `signUp` in `AuthStore`, `allowSignUp` is `false`. An account comes from an account link of an admin (`/admin/users`, then `/welcome/:token`) or from an editor invite (`/invite/:token`, which loads the new user through `AuthStore.getMe()` afterwards). The account menu lists "Events" (`/events`) for every signed-in user, and for admins "Konten verwalten" (`/admin/users`) below it. The admin area (`/admin/users`, `/admin/legal`) has the tabs "Konten | Rechtsseiten"
- **Token pages**: `/welcome/…`, `/invite/…`, `/rsvp/…`, `/photos/…`, `/stand/…` and `/save-the-date/…` are answered with `Referrer-Policy: no-referrer` by the Express server ([token-pages.ts](../../apps/vyte-web/src/server/token-pages.ts)), so a token does not leave the site through a link on the page
- **Navigation**: the host pages navigate through breadcrumbs (`Events › <Titel> › Bearbeiten`) as well as the header. A signed-in user sees "Events" (`APP_NAV_ITEMS`) in the header and the mobile drawer, an admin also "Verwaltung" (`ADMIN_NAV_ITEMS`, `/admin`, which opens `/admin/users`). Signed out, both show no navigation. The logo leads to `/`, which sends a signed-in user to `/events`
- **Times**: vyte is used in one country. A new event stores the zone of the host's browser, the form builds its instants in that zone, no zone field. Every page shows times through `localDate` with the zone of the event, so the server (UTC) renders the same times as the browser. The rules of start, end and deadline are in `features/events/domain/event-times.ts`. Dates that belong to nothing with a zone (since when an account exists, until when a link is valid) use `APP_TIME_ZONE` (`Europe/Berlin`, [time-zone.ts](../../apps/vyte-web/src/app/time-zone.ts))
- **App shell**: reads `shellLayout()`, so a page can ask for the full width, as in `portfolio-web`. The logo is `public/logo-full.svg`: the app icon (the yellow tile with the V) next to the wordmark `vyte`, drawn as paths from Unbounded ExtraBold, so it needs no font. On the yellow ground of the guest pages `logo-full-on-brand.svg` with the tile in ink. `logo.svg` and the PNG icons stay the app icon alone
- **Previews of shared links**: the default image is `public/og-image.png` (1200 × 630, logo, "Einladungen, die ankommen" and the invitation in a phone). The invitation and the save the date use the cover of the event instead, as a JPEG the API cuts to 1200 × 630 (`/rsvp/:token/preview`, `/save-the-date/:token/preview`, `PreviewImage` in `src/api/preview-image.ts`), and describe the event with date and place name, never with the address or the name of the guest. The upload pages keep the default image and say whose photos they collect
- **Guest fields**: on the guest pages text fields take the Konfetti shape of the design, 3px ink border and the control radius (`styles/base/_guest-fields.scss`, keyed on `.guest-shell`, outside a layer so it wins over the Tailwind border utility). The invalid state keeps its red border, the focus outline comes from `FormControlShell` in `--ring`
- **Guest shell**: the pages a guest or visitor opens through a link (`/rsvp/:token`, `/save-the-date/:token`, `/photos/:token`, `/stand/:token`) sit in [GuestShell](../../apps/vyte-web/src/app/layout/guest-shell/guest-shell.ts) instead of the app shell, as a top-level route before it: the yellow ground of the design, the wordmark as plain text (no link away from the page), the legal links and at most two decorative shapes that never sit behind text. No header, no sign-in, no account menu. The guest page sets `--form-choice-border` and `--form-choice-radius`, so the answer tiles of `app-form-radio-group` and the stepper take the Konfetti shape
- **Words for roles**: the event roles read "Gastgeber" (`owner`) and "Mitplaner" (`editor`), in English "Host" and "Co-host". Guests call everyone of the team "die Gastgeber". Accounts only carry a label when they are admins, every account hosts events. Actions keep one name through the app: "Link kopieren", "Link erneuern", "Zurückziehen"
- **Team**: the role of the signed-in user on the team page comes from the loaded members and `AuthStore.me()`, not from the event, so it follows a handover at once. The invites are only requested for the owner (the API answers 403 to an editor)
- **Uploads**: one photo per request, one after the other. The progress is per photo (waiting, uploading, failed with retry) plus a count of the chosen ones, not a percentage: the default `fetch` backend of Angular cannot report upload progress, and switching the app to `withXhr()` was not worth it. Files of another type than `PHOTO_TYPES` and more than are left are not sent
- **Event frame**: `/events/:id` loads `EventFrame` of the `events` feature (it provides `EventsUseCase` and `EventsStore`, the overview shares them). Its children in `app.routes.ts` are the overview, the save the date and the photo stand (all three of the `events` feature, sharing the store of the frame) and the features `guests`, `team` and `photos`, which read the `id` of the frame through `paramsInheritanceStrategy: 'always'`. The frame stays while the user switches tabs; each tab still loads the event for its own needs. `/events/new` and `/events/:id/edit` stay in the `events` routes, which come first: a path they do not know falls through to the frame
- **Query-only navigation**: the app shell moves the focus to the new page after a navigation, but not when only the query changes (a filter, a sort): the focus stays on the control, unless that element is gone, then `<main>` takes it. A link with a fragment (the pages of the guest list) focuses that element if it has `tabindex`. Filters navigate with `scroll: 'manual'`, so the page does not jump to the top
- **Guests**: a guest is addressed with "du": an invitation goes to one person, who may bring companions. The host pages count from the loaded list (`countGuests()` in `features/guests/domain/guest-list.ts`), so the counts follow every change at once. The dialogs of the guest list get a `save` function and its state from the page, stay open while saving and show a failure themselves
- **No notes, no showcase**: the reference features of the base are left out
- **SEO**: `/` is the only page in the sitemap, everything else is behind the sign-in or behind a personal link
- **Legal pages**: not static as in `angular-base`. There is no `SITE_OWNER` and no i18n JSON of the pages in the app. `LegalPage` (`features/legal`) loads the HTML of the page from `vyte-api` through `src/api/legal` for the active language and renders it with `app-ui-rich-text profile="page"`, so the links inside it go through the router. The four pages are `/imprint`, `/privacy`, `/accessibility` and `/cookies`, the last one is also in the footer. The texts are edited under `/admin/legal`, the start content comes from the seed of `vyte-api`, see [vyte-api](vyte-api.md#legal-pages). The pages are `index: false`
- **Config**: [config/app-config.json](../../apps/vyte-web/config/app-config.json) with `apiBaseUrl` ending in `/api/v1`
