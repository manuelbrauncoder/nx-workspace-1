# vyte-contracts

The wire format between `vyte-api` and the vyte web app: the limits of events, guests, photos and legal pages, and the schemas of the event, guest, team, photo and legal page routes. Like `contracts`, it takes nothing from npm but `zod`. The sign-up schema of an editor invite comes from `@contracts/auth`, the one shared lib it imports.

| Item    | Value                                                                                                                              |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Folder  | [packages/vyte/contracts](../../packages/vyte/contracts/src)                                                                       |
| Alias   | `@vyte/contracts/*`, e.g. `@vyte/contracts/events-limits`                                                                          |
| Tags    | `type:contract`, `scope:vyte`                                                                                                      |
| Used by | `vyte-api` (events, guests, guest links, team and editor invites, save the date, photos, legal pages), the API layer of `vyte-web` |

## Contents

| File               | What it holds                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `events-limits.ts` | `EVENT_TITLE_MAX_LENGTH`, `EVENT_DESCRIPTION_MAX_LENGTH`, `EVENT_LOCATION_NAME_MAX_LENGTH`, `EVENT_ADDRESS_MAX_LENGTH`, `SAVE_THE_DATE_NOTE_MAX_LENGTH`, `EVENT_IMAGES_MAX`, `EVENT_EDITORS_MAX`, without Zod                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `guests-limits.ts` | `GUEST_NAME_MAX_LENGTH`, `GUEST_NOTE_MAX_LENGTH`, `GUEST_MESSAGE_MAX_LENGTH`, `GUEST_COMPANIONS_MAX`, `EVENT_GUESTS_MAX`, `GUESTS_BULK_MAX`, without Zod                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `events.ts`        | Zod schemas of the event routes: create and update input, the image order, the params, the responses (`eventSchema` with `role`, `past`, `images`, `counts`, `saveTheDate`), the types `*Dto` and `*Input`, plus `isTimeZone()` and `eventTimesError()`. `eventCountsSchema` is the guest list in numbers, see section 5 of the [specification](../vyte/spec.md#5-guest-list-overview). The save-the-date schemas: `saveTheDateSettingsSchema` (the input, empty note means none), `saveTheDateSchema` (what the public link shows, after the event only the title) and the params and responses. `photoStand` in `eventSchema` is the link of the photo stand, `null` while it is off |
| `token.ts`         | `tokenSchema`: 43 characters of base64url, the form of every personal link. `guests.ts` re-exports it, `events.ts` uses it for the save-the-date link and the photo stand                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `guests.ts`        | Zod schemas of the guest routes for the hosts (`guestSchema` with the token, `companionsReduced`, the bulk and host answer inputs, `guestsExportQuerySchema` with `lang`: `de` by default, or `en`) and of the public guest link (`rsvpSchema`, `invitationSchema`: the event without guest list, the own guest, or only the title once the event is past), the types `*Dto` and `*Input`. `photoToken` is the photo link of the place card, which only allows uploads. `tokenSchema` (re-exported from `token.ts`) checks the 43 characters of a token                                                                                                                                |
| `team.ts`          | Zod schemas of the team routes: the params, the hand-over input, `memberSchema` (`userId`, `name`, `email`, `role`, `joinedAt`), `editorInviteSchema` for the owner (with the token), `publicEditorInviteSchema` for the link (no email, the owner's name only if set), `inviteSignUpSchema` (the `signUpSchema` of `@contracts/auth`, name optional), the responses and the types `*Dto` and `*Input`                                                                                                                                                                                                                                                                                 |
| `photos-limits.ts` | `PHOTO_UPLOADER_NAME_MAX_LENGTH` (60), the name a stand visitor may type, without Zod. The counts of photos are config of `vyte-api`, not constants, and come with every upload answer                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `photos.ts`        | Zod schemas of the photo routes: the params of the photo link, the stand and the host routes, `standUploadSchema` (the optional `name`: trimmed, at most 60 characters, no invisible characters, empty means none), `hidePhotoSchema`, `photoSchema` for the hosts (with `source`, `uploaderName`, `hidden`), `ownPhotoSchema`, `uploadSchema` (the upload page: event title, guest name or `null`, own photos, `limit`, `left`, `open`, `opensAt`, `closesAt`), the responses and the types `*Dto` and `*Input`                                                                                                                                                                       |
| `legal-limits.ts`  | `legalPageKeys` (`imprint`, `privacy`, `accessibility`, `cookies`) and the type `LegalPageKey`, `LEGAL_PAGE_MAX_LENGTH` (100 000 characters per language), without Zod                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `legal.ts`         | Zod schemas of the legal page routes: `legalPageInputSchema` (both languages), `legalPageUpdateSchema` (one or both, at least one), `legalPageSchema` (`de`, `en`, `updatedAt`), `legalPagesSchema` (every page, `null` until created), `legalQuerySchema` (`lang`: `de` by default, or `en`), the types `*Dto` and `*Input` (`LegalPageDto`, `LegalPagesDto`, `LegalPageUpdateDto`). It re-exports the limits of `legal-limits.ts`                                                                                                                                                                                                                                                    |

The numbers come from section 3 of the [specification](../vyte/spec.md#3-domain-model). `events.ts` imports the limits from `events-limits.ts`, `guests.ts` from `guests-limits.ts`. As in [dartomat-contracts](dartomat-contracts.md), the web app imports only the types from the schema files and the constants from the limits, so Zod stays out of its bundle.

Only projects with `scope:vyte` may import this lib.
